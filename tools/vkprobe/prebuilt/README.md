# Prebuilt `vkprobe.exe`

x86_64 Windows build, for running **inside a Winlator container**.

Committed as a binary because Termux has no mingw-w64, so it cannot be built
on the phone. Rebuild from source any time with `../build-windows.sh` — the
source is `../vkprobe.c` and nothing here is generated by hand.

## Why a Windows build exists

A Termux binary reaches the Android system loader, which is the Qualcomm
proprietary driver. It **cannot** reach the Turnip instance AdrenoTools
injects into the Winlator app process — different process, different loader.

This build loads `vulkan-1.dll` → winevulkan → whatever native driver the
container is configured with. That is the same path the game takes, so it
measures what VKD3D-Proton will actually see.

## Use

```
vkprobe.exe --out Z:\sdcard\Download\caps-turnip.json
```

`--out` matters: Winlator's launcher gives you no shell, so `> file.json`
is not available. In Wine, the Android filesystem hangs off `Z:\`.

Then, back in Termux:

```sh
./tools/report.sh /sdcard/Download/caps-turnip.json
```

## Reading the result

Check `driver_properties.driverName`:

| Value | Meaning |
|---|---|
| `MESA_TURNIP` | you measured Turnip — this is the number that matters |
| `QUALCOMM_PROPRIETARY` | the container is on the vendor blob; the custom driver did not take |

A failed run still writes valid JSON with the error recorded, so a container
that cannot initialise Vulkan is diagnosable rather than silent.

## Verification

Built by `build-windows.sh` and smoke-tested under Wine: loads the loader,
queries instance version/extensions/layers, honours `--out` with a `Z:\`
path, and emits valid JSON on both the success and failure paths.
